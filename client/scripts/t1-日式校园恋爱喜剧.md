> **用途**：T1「连续生成 10 章」基线测试的作品输入；同一部书顺延给药 T2（第 5 章后改需求）与 T3（30 → 100 章扩张）。
> **配套**：`mobi/scripts/t1-create.json`（可直接 POST 的建作品 body）、`GPT往来/墨笔v2_下一阶段_真实生成压力测试方案.md`（测试矩阵与通过线）。

## 一、为什么选「日式校园恋爱喜剧」当夹具

不是为了好写，是为了**故意难**。这个题材天然同时压到墨笔最容易被压垮的四根神经：

| 设计点 | 压的是什么 |
|---|---|
| 5 个角色、每章 cast 上限 4 人 | 权限投影 + cast 白名单过滤（写错就串场） |
| 第 1 章埋、第 50 章揭的旧照片 | 长线伏笔召回 = **核心差异化**（普通 ChatGPT 必忘） |
| 会长/母亲/旧部志的隐藏真相 | `findLeaks` 泄漏门禁（早泄一章就算失败） |
| 主角「遇事就炸」→ 第 5 章改成冷静 | T2 定向修改能不能「只改未来、不动历史」 |
| 轻松搞笑 + 校园日常 | 低信息密度章节最容易水/漂移，比打斗戏更能暴露问题 |

## 二、一句话灵感（直接贴进「写下你的灵感」）

> 转学第一天我就把全校公认最完美的学生会长撞进了樱花树下的水池；为了赔罪，我被罚加入只剩一个人的「怪人观察部」，每天替全校写秘密观察记录——可那本旧部志的最后一页，早在三十年前就写好了我的名字。

## 四、目标章节数

**30 章**（T1 只跑第 1–10 章；T3 再改成 100）

> 注意：30 > `OUTLINE_WINDOW`(24)，所以大纲阶段**只会细化前 24 章**，第 25 章之后走滚动规划——这本身也是要被观察的行为，不是 bug。

## 五、创作偏好（7 项白名单，逐项填）

| 字段 | 内容 |
|---|---|
| `style` | 第一人称限知（男主视角）。短句＋吐槽节奏，靠对话落差出笑点，不用华丽辞藻。意象固定在樱花、旧纸页、放学后的部室、雨天的走廊。每章至少两处让人笑出声的对话，结尾留一句轻钩子。 |
| `tone` | 轻快搞笑为主，甜味点到为止；允许每三四章插一章安静温柔的过渡，但不得连续两章沉重。 |
| `pace` | 每章一个独立小事件闭环（观察部接一桩校园怪事），卷末给一次大转折；不拖沓、不复述前情。 |
| `protagonist` | 嘴硬心软，遇事就炸毛，越紧张嘴越毒；行动力过剩，先动手再后悔。 |
| `ending` | 主角查清旧部志最后一页的真相，怪人观察部正式复部，与会长确认关系。 |
| `forbidden` | 禁止超能力／系统／穿越／异能；禁止无铺垫的突然告白；禁止出现真实存在的公众人物；不写露骨内容。 |
| `coreGoal` | 保住即将被撤销的怪人观察部，并弄清三十年前的旧部志为什么写着自己的名字。 |

## 六、主要角色设想（5 人，最终以大纲生成为准）

1. **白石 遥** —— 男主，转学生。嘴硬心软、先动手再后悔，口头禅「这种烂事谁会记啊」（然后每次都真的记下来）。
2. **绫濑 琴音** —— 学生会长。完美到不真实，被家世绑住，私下是怪人观察部唯一的正式部员。
3. **小鸟游 铃** —— 毒舌学妹，情报贩子，观察部编外顾问。什么都懂，就是不说。
4. **藤原 光** —— 男主的损友，吐槽役兼体育生，唯一能当场把男主按住的物理手段。
5. **佐仓 一彻** —— 学生会副会长，秩序派，主张撤销观察部。**动机必须成立**：他姐姐当年因为部志的一则记录被霸凌。

## 八、T1 专有判读点（在方案文档四指标之外）

1. **第 1 章必须同时做到**：正文出现「旧部志 / 那张合照」的可观察描写，且**一个字都不点明**它和主角父母有关。
2. **零越界**：第 1–10 章每章正式出场人物 ≤ 4 人，且都在大纲 cast 白名单内；第 5 号角色佐仓不得在第 1 章就跳出来。
3. **零泄漏**：`findLeaks` 全程拦截为 0；抽取到的 `foreshadows[].action` 在 1–10 章内只允许 `plant` / `reinforce`，**不允许出现 `pay_off`**。
4. **文风不漂**：第 10 章的叙述人称、句长、笑点密度与第 1 章同一档；不得出现「前情回顾」式段首。
5. **成本曲线**：逐章记录 `usage`；若第 10 章输入 token 已是第 1 章的 2 倍以上（上下文膨胀失控的信号），即使文本没问题也要报出来。

## 九、跑法（并产后）

```bash
cd mobi

# 1) 起服（8787）
node server/index.js

# 2) 一条命令搞定：建作品（含 7 条偏好）→ 连续生成第 1–10 章 → 落 JSONL
node scripts/live-stress.mjs --create scripts/t1-create.json --from 1 --to 10 \
  --out records/t1-chapters.jsonl
```

> `live-stress.mjs` 的 `--create <body.json>` 会把整份建作品 body（含 `preferences`）原样 POST 给 `/api/projects`，因此**偏好不会丢**。风险章（揭示秘密 / 回收伏笔）默认自动 accept 并记录 `autoAccepted`。
> 也可拆两步：先 `curl` 建作品拿 `p_xxx`，再 `--project $PID` 跑；或只给 `--idea/--tags/--target`（可再配 `--prefs <文件>`）。

### 后续两步的 payload

```bash
# T2（第 5 章写完后）：把主角从「遇事就炸」改成「冷静」
curl -s -X POST http://127.0.0.1:8787/api/projects/$PID/author-settings \
  -H 'Content-Type: application/json' \
  -d '{"preferences":{"protagonist":"冷静、话少、观察力极强；用冷淡的毒舌代替炸毛，动手前先算三步。"}}'

# T3（30 → 100 章）：改计数只会打上 pendingReplan，必须再显式重排
curl -s -X POST http://127.0.0.1:8787/api/projects/$PID/author-settings \
  -H 'Content-Type: application/json' -d '{"targetChapters":100}'
curl -s -X POST http://127.0.0.1:8787/api/projects/$PID/replan
```

> T2 改动前后**各算一次第 1–5 章的 `contentHash`**，两者必须相等——这是 T2 唯一的关键取证。
