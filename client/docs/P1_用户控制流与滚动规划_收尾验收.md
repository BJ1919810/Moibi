# 墨笔 v2 · P1 / 用户控制流收尾记录

版本日期：2026-10-11。该文档记录**源码中的实际实现**及在当前执行环境完成的验证，不把未运行的前端生产构建、浏览器测试和真实模型任务写成已完成。

## 修复和接线

1. **P1 L1 规划**：`server/creative-options.js` 的初始详细窗口由 24 章改为最多 5 章；`prompts.js` 要求三幕和全书分卷里程碑，但对开篇章节仅建议 3～5 章。`pipeline.normalizeOutline()` 接受 30 章目标对应的 3、4、5 章明细，超过窗口时截取前 5 章，剩余生成 `pendingDetail` 占位，并保留 `volumeMilestones`。缺角色、缺章节、不足最小章节数时显式失败，绝不把无效输出标成成功。
2. **空大纲存储/重试**：创建失败时持久化 `status='outline_failed'`、`outlineError` 和错误时间，不把空大纲标成成功。已有成功大纲的重新生成失败不会抹去旧资料。目录无有效章节时重新显示「重新生成大纲」入口。
3. **正文空结果**：`server/workflow.js` 只在模型确认空正文（包括 ProviderError 的空正文情况）时追加**最多一次**关闭 `thinking` 的请求；空正文首次请求及补发请求的 usage 均保存在 Run，第二次为空则 `needs_input`，不提交正文和账本。网络/超时/非空截断等其他异常不会偷偷重发。旧版导出函数 `pipeline.generateChapter()` 也添加一次空正文降级保护；正式 API 仍走 workflow。
4. **真正的 5 章滚动细化**：增加 `createReplanService.create(...,{mode:'window'})` 和 `applyRollingWindowPlan()`。只填下一组连续占位，不覆盖已确认章节、不覆盖其他未来规划，角色/伏笔外键必须属于现有实体表，`writerTaskApproval='proposed'`。目录显示按需细化按钮；`workflow.createRun()` 阻止未细化占位直接生成正文。低权限逐章 L2 仍由原有投影/泄密自检约束。
5. **高风险全局重排**：原始 `pendingReplan` 冻结门禁保留，重排使用每批最多 5 章的模型调用；CAS 提交成功后设置 `pendingReplan=false`、`outline.plannedDetailThrough=target`，不触碰已定稿正文。与“普通滚动细化”模式互斥。
6. **UI 回退修复**：恢复空大纲重试、已生成未写作品的「重新构思大纲」按钮；更新新建页篇幅说明（不再错误地说前 24 章）；创作资料三幕页展示卷级里程碑，静态缓存版本更新以减少旧前端残留。

## 验证（真实执行）

- `node --test`：197/197 通过。原有 188 项基础上新增 9 项专项回归，覆盖 P1 弹性、空/非法 L1、首次空正文补发、连续空正文拒绝提交、ProviderError 用量保留、非空故障不重复请求、滚动窗口守恒、高风险确认→重排→解锁、HTTP 模拟供应商空响应。均采用模型替身，不消耗真实模型 token。
- 后端 `.js/.mjs` 的 `node --check` 全通过；解析 143 条相对 import，未发现缺失文件。
- 本机 HTTP 冒烟（端口 19387、无密钥）：健康检查成功；新建作品在无密钥时返回 `outline_failed` 并持久化；`POST /outline` 重试返回 HTTP 500，仍保留失败状态；测试作品随后删除。
- `npm run build` 未成功：本执行环境 Vite 不存在且 npm 软件源域名解析失败。**本包不带旧 `dist`，不得把本验收视为已执行新版 Vite 构建或浏览器验收。**
- 未执行真实付费模型 T1 连续十章/三十章：本环境没有可用的真实模型密钥及访问网络。P1 逻辑和模拟调用已测试，但真实模型输出质量、成本和供应商兼容性仍需外部环境验收。

## 收包与部署

本包顶层 `mobi/`。只覆盖源码、文档和测试；**不要覆盖用户原有 `mobi/data/` 作品、密钥、runs，先备份生产目录**。随后在正常可连接 npm 的本地电脑运行：

```bash
cd mobi
npm ci
npm run build
npm test
npm start
```

验收建议：用全新无隐私测试作品创建 30 章目标，核对三幕 + 开篇 3～5 章，完成占位前细化，再做一次高风险角色/主题修改、确认、重排和 2 章连续生成；模型 API 会真实计费。正式发布前还需要进行浏览器和手机端交互检查。
