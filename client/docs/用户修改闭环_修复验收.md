# 墨笔 v2 · 用户修改闭环修复与验收

## 这次实际改了什么

- **真实修改请求**：`server/change-request.js` 通过 `createChangeService()` 校验服务器端白名单，生成 24 位随机 ID 的持久化 `data/changes/cr_*.json`。草稿不写作品；确认时重新读取当前项目、校验 `headVersion` 与 `editRevision`，CAS 提交后写入带请求 ID 的项目审计 `editEvents`。旧请求标记 stale；重复确认依托权威项目审计恢复，不重复提交。
- **影响分析**：`server/change-impact.js` 从作品大纲实际章节出场名单、伏笔动作、已定稿章节以及未来章节读取关系，而不是根据一句话的关键词假定风险。高风险修订标记 `pendingReplan`，正常写章入口阻止在旧计划上继续生成；重排使用既有受控 `replan` 服务，不修改已定稿正文。人工修改不会覆盖账本。
- **真实资料编辑**：`src/components/CreationDrawer.jsx` 包含主题、三幕、角色卡、世界观、伏笔、剧情方向和偏好/目标章数的编辑草稿、影响预览、确认/取消。目录默认优先。AI 抽屉真实调用后端 AI 提议，确认按钮不用手打口令。AI 提议确认在正式仓库也通过 ChangeRequest 通道。
- **单章指令**：对未写章节保存 `authorInstruction`，经 WriterPacket 编译器的 `findLeaks` 守卫后交给写作/安全 L2，防止不经审批披露作者秘密。
- **兼容**：保留现有章节 ledger、projection、head 版本及 run 工作流。删除直接写项目 `/author-settings` API（HTTP 410），防止跳过新控制流。

## API

- `POST /api/projects/:id/changes`：只允许白名单字段并可带 `expectedHeadVersion` / `expectedEditRevision`，返回 `{request}`（HTTP 201），不会写正式项目。
- `GET /api/projects/:id/changes`：返回 `{requests}`。
- `GET /api/changes/:id`：查看预览与状态。
- `POST /api/changes/:id/approve`：返回 `{request, project}`，会 CAS 提交；版本冲突返回 409。
- `POST /api/changes/:id/reject`：放弃请求。

支持的 `kind`：`rename`、`character_field`、`theme`、`act`、`world`、`plot_direction`、`foreshadow`、`chapter_intent`、`preferences`、`preferences_bulk`、`target_chapters`、`book_title`、`chapter_title`、`reader_intro`。不允许直接写 ledger、秘密揭示批准、安全投影策略或已定稿正文。
